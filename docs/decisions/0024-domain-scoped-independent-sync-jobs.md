# ADR-0024：初始同步按业务域拆分为独立 SyncJob

- 状态：Accepted
- 日期：2026-07-28

## 背景

账号首次接入需要同时建立商品、会话/消息、订单/评价的历史上下文。三个数据域的接口、数据量、平台权限和失败原因不同；把它们做成一个不可拆分的全量任务，会让进度、重试和部分成功难以表达。

## 决策

初始同步采用默认顺序：

```text
商品 → 会话与消息 → 订单与评价
```

但每个业务域都建立独立的 `SyncJob`，拥有自己的游标、检查点、进度、缺口、错误和重试状态。一个域的失败或部分完成不回滚其他域。账号在基本 Runtime 可用后，可以先提供已经完成域的 Query 和 Event；未完成域以 `partial` 或 `syncing` 明确标识。

同步 Command 只针对一个 `account_id`。初始同步可以一次声明多个域，由系统拆成多个域任务；增量、缺口修复和重新校准按单域执行。

## 结果

- 历史同步可以后台分批执行，不阻塞账号基本可用；
- 单域可以独立暂停、重试、补缺口和审计；
- 游标和检查点不会被其他域的失败覆盖；
- 上层调用者可以清楚区分“还没同步”“部分同步”“同步失败”和“平台要求重新登录”；
- 标准 API 只暴露稳定的同步对象，不暴露 App 原始分页协议。
