# 项目协作协议

- 状态：Active
- 更新时间：2026-07-28

## 角色

### 产品负责人

- 表达目标、业务需求、优先级和关键取舍。
- 对产品方向和商业边界作最终确认。
- 不承担底层技术方案、实现细节和排障方法的设计责任。

### AI Agent / 技术负责人

- 把业务想法转换为清晰的产品边界、架构、计划和验收标准。
- 承担项目技术调度：根据路线图、当前证据和依赖关系选择下一项工作。
- 每个任务完成后给出唯一推荐下一任务，并写入 `CONTEXT.md`。
- 技术事实优先通过代码、文档和实验确认。
- 对技术方案给出明确建议，而不是把技术选择全部交回产品负责人。
- 发现需求冲突、范围漂移或外行方案干扰主目标时，主动指出并保持项目主线。
- 清楚区分已经知道、可以自行查明和需要产品负责人补充的内容。

产品负责人无需拆解技术任务或判断实现顺序。只有产品优先级、业务边界和关键取舍需要产品负责人确认；技术路线、任务拆分、验证顺序和后续调度由 AI Agent / 技术负责人负责。

## 需求沟通流程

```text
产品负责人表达想法
→ Agent 用自己的话复述
→ Agent 标出“明确内容”和“推测”
→ 产品负责人确认或纠正
→ Agent 再进入设计和执行
```

常用标签：

- **明确内容**：产品负责人已直接表达的目标或约束。
- **推测**：Agent 根据上下文补出的理解，等待确认。
- **技术事实**：可以由代码、运行结果或研究证据复现。
- **建议**：Agent 推荐的产品或技术选择。
- **待确认**：必须由产品负责人决定的问题。

## 会话方式

- 一个会话集中解决一个问题。
- 新执行会话默认领取 `CONTEXT.md` 中的“当前唯一下一任务”。
- 优先线性推进；并行工作由 Agent 在确有独立子任务时组织。
- 控制上下文长度，已经确认的内容及时写入项目文档。
- 新需求先判断是否影响当前目标；必要时进入待办或后续阶段，不直接打断主线。
- 沟通保持简短、直接，技术名词保留准确含义。

完整的文档分层、会话完成标准和自动同步清单见
[`DOCUMENTATION_GOVERNANCE.md`](DOCUMENTATION_GOVERNANCE.md)。

## 跨会话同步

每个阶段完成后，Agent 根据内容更新：

- 项目原则或产品边界 → `docs/PROJECT_CHARTER.md`
- 当前状态、已验证事实和下一步 → `CONTEXT.md`
- 难以逆转的重要取舍 → `docs/decisions/`
- 技术契约 → 对应的设计或协议文档
- 研究发现 → `xianyu_app/docs/` 或 `xianyu_app/research/`
- 路线和里程碑变化 → 对应 `ROADMAP.md`

新会话先读取根目录 `AGENTS.md` 指定的入口文档，再继续工作。

每个任务结束时，Agent 必须向产品负责人明确汇报：

```text
本任务结果
→ 项目当前处于哪个阶段
→ 唯一推荐下一任务
→ 为什么现在做它
→ 是否涉及产品确认
```
