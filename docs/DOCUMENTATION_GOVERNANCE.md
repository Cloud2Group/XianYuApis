# 项目文档治理与会话同步规则

- 状态：Active
- 更新时间：2026-07-28

## 目的

让多个 Codex 会话可以线性接手同一个项目。项目状态、已确认决策、技术事实和下一步都进入工作区文档，聊天记录只作为过程，不作为唯一依据。

## 文档分层

| 层级 | 文档 | 领导内容 |
| --- | --- | --- |
| L0 | `docs/PROJECT_CHARTER.md` | 为什么做、产品边界、长期原则 |
| L1 | `docs/DOMAIN_MODEL.md`、`docs/CAPABILITY_MAP.md` | 领域对象、关系、能力范围和优先级 |
| L2 | `docs/ARCHITECTURE.md`、`docs/HEADLESS_WORKER.md` | 分层、组件边界、数据流和部署演进 |
| L3 | `docs/ROADMAP.md` | 阶段顺序、里程碑和验收门槛 |
| L4 | `docs/API_CONTRACT.md`、`docs/api/` | Query、Command、Event 和业务契约 |
| ADR | `docs/decisions/` | 难以逆转的取舍及其原因 |
| 状态 | `CONTEXT.md` | 当前进度、已验证事实、阻塞点和下一步 |
| 导航 | `docs/PROJECT_MAP.md` | 文件位置、职责和接手顺序 |

## 文档领导关系

```text
PROJECT_CHARTER（目标和边界）
        ↓
DOMAIN_MODEL / CAPABILITY_MAP（对象和能力）
        ↓
ARCHITECTURE（系统怎么分层）
        ↓
ROADMAP（先做什么）
        ↓
API / 研究文档（具体怎么验收）
        ↓
CONTEXT（现在做到哪）
```

ADR 横向记录会影响多个层级的关键决策。出现冲突时，优先级为：最新已确认产品决策 → 相关 ADR → L0-L4 设计文档 → 研究推测 → 聊天中的临时说法。

## 新会话开始规则

每个新会话先按以下顺序读取：

1. 根目录 `AGENTS.md`；
2. `PROJECT_CHARTER.md`；
3. `WORKING_AGREEMENT.md`；
4. `CONTEXT.md`；
5. `PROJECT_MAP.md`；
6. 按任务进入 App、Web 或具体 API 文档。

新会话先确认当前目标和下一步，再开始查代码、实验或编辑文件。

## 会话内记录规则

所有新信息先归类：

| 标签 | 记录方式 |
| --- | --- |
| `技术事实` | 记录来源、命令、时间和可重复证据 |
| `产品决策` | 等产品负责人确认后写入对应设计文档 |
| `架构决策` | 写入 ADR，并在相关架构/契约文档加引用 |
| `推测` | 明确标注依据和待验证条件 |
| `任务结果` | 记录改动文件、验证命令、结果和遗留项 |

技术细节优先通过代码、静态证据和实验确认；产品负责人只需要确认目标、边界和关键取舍。

## 会话结束同步清单

会话完成前逐项检查：

- 新产品边界或原则已写入 `PROJECT_CHARTER.md`；
- 新领域对象或关系已写入 `DOMAIN_MODEL.md`；
- 新能力范围或优先级已写入 `CAPABILITY_MAP.md`；
- 新架构边界已写入 `ARCHITECTURE.md` 或 `HEADLESS_WORKER.md`；
- 新阶段或验收门槛已写入 `ROADMAP.md`；
- 新接口字段、状态、错误和事件已写入对应 API 文档；
- 难以逆转的取舍已建立 ADR；
- 当前状态、事实、阻塞点和下一步已更新 `CONTEXT.md`；
- 新文件和目录已更新 `PROJECT_MAP.md`；
- 相关测试、实验或静态检查已执行并记录结果；
- 凭证、Cookie、聊天隐私数据和本机快照仍位于 Git 忽略路径。

## 完成标准

一个会话只有同时满足以下条件才算完成：

1. 用户提出的问题得到明确结论或明确的待验证项；
2. 结论已经进入正确层级的文档；
3. 实现或研究结果有可复现的验证记录；
4. `CONTEXT.md` 指向下一步；
5. 新会话按照入口文档即可接手，不依赖本会话全文。

如果工作因外部条件暂停，仍然记录已完成部分、具体阻塞条件和恢复动作，状态写入 `CONTEXT.md`。

## 变更和冲突规则

- 已确认的产品决策优先于 Agent 临时建议；
- 技术事实优先于未经验证的推测；
- 文档发生冲突时，先在 `CONTEXT.md` 标出冲突，再通过新 ADR 或产品确认解决；
- 旧决策被替代时保留原 ADR，并在新 ADR 中写明替代关系；
- 文档只记录当前有效语义，实验原始输出放在对应研究目录。

## 自动同步语义

“自动同步”指：在当前工作区内完成会话结果的即时文档更新，并让下一会话从固定入口读到最新状态。它不依赖聊天历史，也不要求用户手工复制摘要。

默认同步目标是：

```text
决策 / 事实 / 设计 / 代码验证
          ↓
对应专题文档
          ↓
CONTEXT.md + PROJECT_MAP.md（需要时）
```

只有在文件系统或外部工具暂时不可用时，才把待同步项列入 `CONTEXT.md` 的下一步清单。
