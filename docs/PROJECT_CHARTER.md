# XianYuApis 项目总纲

- 层级：L0
- 状态：Active
- 更新时间：2026-07-28

## 文档职责

本文件回答项目为什么存在、最终要成为什么，以及长期保持哪些产品原则。技术实现、阶段进度和研究证据分别记录在架构、路线图、契约和研究文档中。

## 使命

将每个闲鱼账号变成长期在线、可调用、可恢复、可审计的数字化运营单元，逐步降低闲鱼卖货过程中需要投入的人工时间。

## 产品第一身份

XianYuApis 首先服务于项目方自己的运营业务。第一阶段的具体产品是完整、稳定、可独立调用的“闲鱼能力 API 基座”；内部闲鱼运营系统建立在该基座之上。

托管账号平台、对外 SaaS、第三方 API 和账号合作分佣属于建立在内部运营系统之上的后续商业形态，不作为第一阶段的产品身份。

## 长期愿景

通过统一 API、AI Agent 和多账号控制系统，把询单、沟通、商品管理、成交和履约逐步自动化。先建立稳定的单账号运行时，再复制到大量账号，形成闲鱼自动化运营基础设施。

## 产品形态

```text
第一层：闲鱼功能实现
收消息、发消息、上架、改价、擦亮、下架等
        ↓
第二层：标准闲鱼 API
指定账号 + 操作参数 → 执行 → 返回结果
        ↓
第三层：调用适配
普通程序、第三方软件、AI 工具
        ↓
第四层：业务决策与编排
AI 规则、多账号策略、商业模式、人工接管
```

## 已确认原则

- 单账号稳定运行优先于账号数量。
- 项目知识进入文档，跨会话共享，不依赖单个长会话。
- 阶段验收按能力质量，而不是 API 数量；每个能力都要有调用入口、明确结果、失败状态、重试路径、可观测性和操作记录。
- API 能力层与 AI/业务决策层严格分离；底层保证可靠执行，上层决定何时执行以及执行什么业务策略。
- 生产执行架构只使用 App 原生协议和状态；Web/Cookie 不作为生产能力或回退通道。

## 第一阶段使用者

- 平台负责人：定义业务目标、优先级和关键取舍。
- 内部技术和运营人员：通过脚本、测试工具或内部客户端调用并验收 API。
- 账号主：提供账号并参与后续收益分配；第一阶段不直接操作运营系统。
- AI Agent 和第三方开发者：属于后续 API 调用者，不是第一阶段建设重点。

## 第一阶段交付形态

当前阶段以“能力基座验证”为目标，不绑定具体在售商品，也不以完成一条商业卖货闭环作为验收条件。

每个能力先作为独立、可调用、可观测的功能单元跑通，后续再把多个单元编排成自动化流程。当前第一组能力仍按项目路线优先验证单账号原生 IM。

## 核心 API 边界

核心 API 负责：

- 选择并确认目标账号；
- 校验操作参数；
- 调用对应闲鱼能力；
- 管理幂等、队列、超时和执行级重试；
- 返回成功、失败、错误和平台结果；
- 记录日志、审计信息和账号运行状态。

核心 API 不负责：

- 判断业务上是否应该执行；
- 决定回复内容或砍价幅度；
- 选择商业模式；
- 判断何时转人工；
- 编排 AI 或多账号运营策略。

## 第一阶段北极星

所有声明支持的闲鱼操作，都可以在单账号上通过标准 API 重复执行，并返回确定、可追踪的结果。

正常状态下，业务操作不依赖人工点击 App。成功、失败、超时、登录失效和需要平台验证等情况必须返回明确状态，并保留完整操作记录。API 数量用于表示覆盖进度，可靠执行才是第一阶段的核心指标。

## 第一阶段平台范围

第一阶段只面向闲鱼。内部能力边界预留适配器扩展点，但暂不建设淘宝、抖音或其他平台的统一产品层。

## 长期账号运行原则

每个闲鱼账号对应一个独立的逻辑 `Account Runtime`，保存该账号的登录态、设备身份、消息连接、操作队列和运行状态。

逻辑账号与物理设备不要求一一对应。未来多个 Account Runtime 可以运行在共享机器、Worker 或设备池中，但每个账号的状态、凭证、操作和日志必须隔离。

当前阶段通过真实闲鱼 App 和 Native Bridge 验证原生能力；长期目标是运行复用 App 原生协议、登录态和设备态的 Headless App Worker。

## 合作账号主关系

合作账号主是账号资产提供方，平台是受托运营方。

- 账号所有权属于账号主；
- 平台获得可撤销的卖家运营授权；
- 日常商品、消息和订单操作由平台执行；
- 账号主可以查看账号状态、运营记录和收益；
- 账号主可以终止合作，平台随后清除对应登录态；
- 平台默认权限只覆盖卖家运营；
- 实名、安全资料和资金操作需要单独授权；
- 所有平台操作保留审计记录。

## 产品能力范围

“完整闲鱼能力 API”指覆盖闲鱼卖家运营的核心能力，不以复制整个闲鱼 App 为目标。

核心范围：

- 账号、登录态和在线状态；
- 消息和会话；
- 商品发布、编辑、改价、擦亮、上架和下架；
- 订单、发货、退款等履约能力；
- 评论、评价和卖家互动；
- 图片、视频等业务媒体能力；
- 操作状态、平台异常和验证事件。

暂缓范围：

- 闲逛推荐和社区内容；
- 作为买家的购物流程；
- 资金提现；
- 实名和账号安全资料修改。

## 已决定暂缓

- 具体商业闭环：待底层能力稳定后再选定。
- AI 自动运营、业务规则和人工接管：作为 API 之上的组合层后续建设。
- 多账号运营策略和规模化调度：单账号能力稳定后建设。
